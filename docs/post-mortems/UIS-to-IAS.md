# UIS to IAS
This is just a lil' anecdote about how hard it was for me to switch from UserInputService (UIS) to InputActionSystem (IAS).

## Getting Accustomed to UIS
As I began developing on Roblox, I always used UIS to map user inputs to in-game actions, though mostly for simple actions such as sprinting and shiftlock.  

However, once I got the bright idea to start working on Crusaders towards the end of May, I took this practice of using UIS to the next level. Not only did map user inputs to sprinting and shiftlock, but I mapped them to everything else! This included the M1s, non-damaging techniques, and character-exclusive bare-style and weapon-style attacks.  

And just when I thought I was making amazing progress... while I was refining my UIS-based code for the character-exclusive attacks, I scrolled through the Roblox Developer Forums for advice and noticed that a lot of developers were switching to IAS. Everyone was calling UIS deprecated, so I investigated why, only to realize how much better IAS is than UIS!

## Switching to IAS
As much as I wanted to stick to coding with UIS, I knew it would be much more beneficial to code with IAS.

IAS is easier to use, and especially more scalable! The biggest reason of all for me to start using it, however, was the fact that other game engines utilized it natively. So, it was with a heavy heart that I revamped my codebase in the middle of alpha development.

Though I wasn't nearly advanced enough in coding to be pulling a stunt like this, I already had an idea for integrating IAS into Crusaders' full system architecture, and I didn't want to forget the idea while it was still fresh in my mind.
